## 二、你要知道的三件事（不用改代码，但会影响你调试）

### 1. 现在不能双击 html 直接打开

云端接口要走 http，`file://` 协议下跨域会被拦。本地调试起个服务：

```bash
python -m http.server 8123
# 或者
npx http-server -p 8123
```

然后开 `http://127.0.0.1:8123/index1.html`。

### 2. 模拟"两个人"必须用无痕窗口

设备身份存在 localStorage 里。**两个普通标签页共享 localStorage，云端会当成同一个人**，你会以为是 bug。开一个正常窗口 + 一个无痕窗口，才是两台手机的效果。

### 3. 真房间从 0 人开始

以前建房后默认有「我 + 张三 + 李四」三个假成员。现在建完房间是空的，要你自己点「开始填写个人信息」进去，才会有第一个成员。**这个时候成员列表区是空白**——需要你补一个空状态（见下面第 4 条）。

## 三、请你做的 5 件事

### 1. 手机尺寸适配（优先）

建房表单里我加了一个「出行城市」下拉框，位置在「目的地」上面。引擎必须有城市才能解析地名，所以这个不能删。

问题：`<select>` 在 iOS Safari 上和 `<input>` 的高度、圆角、内边距都不一样，会露馅。你按你原来的 `.field input` 样式给 `select` 补一套，保证视觉一致。

顺便看下微信内置浏览器（安卓）里 `datetime-local` 的显示，那个控件各机型差异比较大。

### 2. 成员卡片上的「我」

原来靠 `isMe` 字段判断。现在靠设备令牌比对（`row.member_token === Cloud.deviceToken()`），逻辑在 `mapCloudMember()` 里，已经处理好了，**你不用动**。

但要帮我看一件事：真房间里可能有两个人都叫「小明」，卡片会重名。建议在「我」那一张加个明显的视觉标记（你原来用 `（我）` 后缀，够用，确认一下手机上看不看得清就行）。

### 3. 房间有效期提示（新需求）

房间数据**存在服务器上，7 天后自动清理**。这是我们的设计取舍：不注册、不登录、不留长期数据。

但对用户来说 7 天后房间突然没了会很懵。请在房间页顶部加一行小字，比如「房间有效期还剩 X 天」，或者用你喜欢的样式做。数据在 `room.expire_at`，我已经存进 `state` 的话可以现算，没有的话我加一个字段给你。

### 4. 空状态

两处：

- 房间里一个人都没有时（刚建完房），`#membersList` 是空的，现在什么都不显示。需要一句引导，比如「把邀请码发给伙伴，他们填完就会出现在这里」
- 方案还没生成时，「查看出行方案」按钮是隐藏的，成员会不知道要等。可以在房间页加一句提示，等发起人生成

### 5. 断网/失败的提示

现在失败只有底部 toast 一闪而过。如果成员在房间里断网了，轮询会静默失败，他会一直看着旧数据不知道出问题。

建议在房间页顶部加个状态条：正常时不显示，连续几次同步失败时显示「当前离线，正在重试」。需要的话我把轮询的失败次数暴露给你。

## 四、有个东西现在是死的，需要你定

**「汇合方式」那个三选一**（全部直达 / 全员汇合 / 部分汇合）。

你原来的设计是：用户选一个，然后按选择生成方案。

但真引擎是**一次算三种方案全都算出来**，然后在结果页并排对比、自动打分排序、标出推荐哪个。用户不需要提前选。

所以现在这个选择器点了只改 `state.selectedPlan`，**不影响任何计算**，纯装饰。

两个处理方式，你选一个：

- **A（我建议）**：删掉。结果页已经有三种方案的对比表，房间页再让用户选一遍是重复的，而且会让人以为"选了才有这个方案"
- **B**：保留，但改成「你更看重什么」这类真正影响计算的偏好（比如"最省钱/最省时/最少等待"），这个引擎支持调权重，我可以接

如果选 A，你直接删那段 HTML 和 `buildPlan()` 里相关的分支就行，我这边没有依赖。
