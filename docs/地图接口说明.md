# 地图接口说明（给组里所有人看）

> 维护人：雷馨怡 · 2026-11-16
> 位置：`js/amap-api.js`（全部高德相关代码都在这一个文件里，`js/map-picker.js` 只调它）
> 谁改了接口行为，谁更新这张表。

## 一、函数一览

| 函数 | 干什么 | 配额消耗 | 失败表现 | 谁来管 |
|---|---|---|---|---|
| `queryRoute(origin, dest, mode)` | 查一条路线：耗时（分）、距离（公里）、费用（元）。mode 只能是 `transit` / `taxi` / `bike`；origin/dest 传地名文字或 `"经度,纬度"` | 地名解析 1~3 次 + 路线 1 次；缓存 30 分钟内同起终点不重复计 | 返回 `estimated: true` 的本地估算值（数字是假的），`fallback` 字段写明原因 | 雷馨怡 |
| `_geoResolve(name)` | 地名 → 坐标。三级解析：geocode（本市）→ inputtips（本市）→ geocode（全国+距离校验） | 每次 1~3 个请求；缓存 30 分钟，失败缓存 60 秒 | 返回 `{ok:false}`，调用方（queryRoute）随即降级估算 | 雷馨怡 |
| `inputTips(keyword, city)` | 输入提示/联想：给关键词返回官方 POI 候选（自带精确坐标），首页出发地/目的地下拉就是它 | 1 次/关键词；5 分钟缓存 | **throw**（带 `tipsFailed: true`），页面显示"联想暂不可用"，可继续手打 | 雷馨怡 |
| `seedCoord(name, lng, lat, adcode)` | 把用户点选的精确坐标预写进解析缓存。之后 engine 里同名地名直接命中，不再发请求 | 0（只写本地缓存） | 永不失败，返回 true/false | 雷馨怡 |
| `regeo(lng, lat)` | 坐标 → 地址（地图选点的地址行就靠它）。REST 接口，radius=200 | 1 次/新坐标；5 分钟缓存（坐标精确到 ~1 米） | **不 throw**，返回 `{ok:false, reason}`，选点界面降级显示坐标 | 雷馨怡 |
| `amapStats()` | 在控制台打印当前请求数、缓存命中、限频重试、降级原因，验收和排查都用它 | 0 | — | 雷馨怡 |

> 另有 `JSXMapPicker`（实为 `JBXMapPicker`，在 `js/map-picker.js`）：出发地地图选点弹层。打开要 1 次 SDK 下载（懒加载，全局只下一次），拖动结束 1 次 regeo/位置。失败时弹层里直接写原因，页面其他功能不受影响。找雷馨怡。

## 二、Key 种类说明（谁不能混用）

| 类型 | 干什么用 | 配置在哪 | 能调的接口 |
|---|---|---|---|
| **Web 服务** | REST 接口：路线、地名、逆地理、联想 | `js/config.local.js` 的 `__AMAP_KEY__` | `restapi.amap.com` 下所有接口 |
| **Web端(JS API)** | 浏览器里画地图（结果页路线图、出发地选点） | `__AMAP_JS_KEY__` + `__AMAP_JS_CODE__` 两行**必须一起填** | `webapi.amap.com` 的 JS SDK |

**不能混用的原因**：拿 Web 服务 Key 去画地图会报 `USERKEY_PLAT_NOMATCH`，反过来会报 `INVALID_USER_DOMAIN`。两种报错都不显示在界面上，只会静默降级，看到"全是估算数据"时先 `amapStats()` 看降级原因。

**安全密钥（jscode）**：2021-12 之后申请的 JS Key 必须配套安全密钥，缺了它地图能"加载"但内容全空、控制台也不一定报错——这是历史上最坑的一种静默失败。**JS Key 还要配域名白名单**，白名单里没有当前域名会报 `INVALID_USER_DOMAIN`（本地调试要加 `localhost`）。

## 三、限频与配额

- 个人开发者 Key：**约 3 次/秒（QPS）**，每日额度在控制台"查看配额"里能看到（路线规划几千次/日）。
- 代码里的三层防护（`js/amap-api.js` 配置区，可调但不许删）：
  1. `MAX_CONCURRENT = 2` —— 并发上限 2
  2. `MIN_INTERVAL_MS = 350` —— 任意两次请求至少隔 350ms（300ms 正好贴着 3.33 QPS，会偶发限频）
  3. `RETRY_MAX = 3` + 线性退避 1s/2s/3s —— 撞到限频自动重试
- 超了会返回 `10004`（QPS 超）或 `10003`（当日额度用完）。前者代码会自己重试消化，后者只能等次日。
- **新增一个成员 ≈ 多 15~20 次请求**（三种方式 × 候选集合点枚举），8 人实测 60 次左右，正常。

## 四、降级策略（哪一步挂了会退化成什么）

| 挂掉的环节 | 退化成 | 用户看到 |
|---|---|---|
| 没配 Key（`config.local.js` 不存在） | 本地估算，一条请求都不发 | 数据是估的，页面正常；`amapStats()` 降级原因显示 `no-key` |
| 地名解析失败（查不到/解析到外省） | 该条路线走本地估算 | 同上，降级原因 `geocode` |
| 路线请求失败（网络/限频 3 次重试后仍败） | 本地估算 | 降级原因 `error` |
| 单次"生成"请求超过 `MAX_REQ_PER_RUN` | 超出部分本地估算 | 降级原因 `budget` |
| 起终点重合（<50 米） | 直接返回 0 | 正常（不是降级） |
| 联想接口失败 | 下拉框显示"联想暂不可用"，可继续手打 | 手打地名走 `_geoResolve` 正常解析 |
| JS API Key 域名白名单没配 | 结果页地图/选点弹层显示错误说明，页面其他功能正常 | 弹层里直接写"当前域名不在 Key 的白名单里" |
| 地图选点里 regeo 失败 | 地址行显示坐标 `114.31,30.59`，仍可确认 | 坐标字符串能被 `queryRoute` 直接当坐标用，功能不断 |

> 估算值的准确性有专门报告：`docs/估算误差报告.md`。答辩引用数据前先看那份报告的结论。
