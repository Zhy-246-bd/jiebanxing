## 第一步：配自己的 Key（每人只做一次）

仓库里**没有** Key（`.gitignore` 排除了），Key 放在你本地一个不进仓库的文件里：

1. 把 `js/config.example.js` 复制一份，改名 `js/config.local.js`
2. 打开它，填进 `g.__AMAP_KEY__ = "你的Key"`
3. 保存，刷新页面

没填也能跑 —— 全部走本地估算，页面不报错，只是数据是估的（控制台 `amapStats()` 里会显示降级原因 `no-key`）。

## 三条铁律

1. **接口签名不许动**：`queryRoute(origin, dest, mode)` 的函数名、参数、返回字段（`durationMin / distanceKm / cost`）是全组交接锚点，改了别人的代码就全崩。
2. **数据格式不许动**：成员 JSON、方案结果 JSON 都定义在 `formats.js` 的注释里，照着写。
3. **改完自测**：双击 `index.html` → 填 3 个人 → 点"生成三套方案" → 结果页能出三张卡片 = 没改坏。

## 怎么跑

**必须用本地服务器打开（重要）**：真接口有跨域限制，双击 `file://` 打开会全部降级成本地估算（页面照常能用，但数据不是真的）。

在骨架目录执行：

```
python -m http.server 8000
```

然后浏览器访问 `http://localhost:8000`。没有 Python 的可以用 VS Code 的 Live Server 插件，效果一样。

- 数据存在浏览器 localStorage 里，刷新不丢；换浏览器/换电脑会重置，正常。
- 手机上调试：电脑和手机连同一个 WiFi，手机访问 `电脑IP:8000`。
- 控制台执行 `amapStats()` 可以看请求数、缓存命中、降级次数——验收和答辩演示都用得上。
- 四个自测脚本：`node test-engine.js`（假数据，秒出）、`node test-engine-v2.js`（27 条算法用例，秒出）、`node test-real.js`（预置城市的真接口，可带参数如 `node test-real.js beijing`）、`node test-any-city.js 长沙`（任意城市，验证在线解析能不能跑通）。

## 城市切换与「任意城市」（v0.5）

录入页顶部有「出行城市」下拉框，预置 **武汉 / 北京 / 上海 / 广州 / 深圳 / 成都** 六个城市（打开就能演示）。
切换后自动完成四件事：地名解析限定该市 → 公交换乘用该市代码 → 中心点校验换成该市 → 候选集合点与示例成员换成该市；同时清空地名缓存（避免“中山公园”在武汉和上海串号）。

**支持全国任意城市**：下拉框最后一项是「＋ 其他城市（手动输入）」，输入城市名（如：长沙 / 西安 / 桂林 / 昆山），
`js/city-online.js` 会自动查这个城市跑起来需要的全部配置，无需改代码：

| 要查的东西 | 用什么接口 | 用来干什么 |
|---|---|---|
| adcode + 中心点 | `v3/config/district` | 公交换乘的城市代码、地名解析的范围校验 |
| 候选集合点 | `v3/place/text` 搜“地铁站”（不够补火车站） | 方案二/三的汇合点，必须是本市真实站名 |
| 目的地示例 | `v3/place/text` 搜“景点”（取市中心 15km 内的） | 录入页输入框的提示文字 |

查到的城市会存进 localStorage（`jbx_custom_cities`），下次打开直接可选，不用重新联网。

**为什么是“查”而不是“配”**：候选集合点如果编一个假站名，地名解析会把它匹配到外省同名的地方，
而且不报错——数据全错但页面正常，这是最难查的一类 bug。所以宁可联网查真实站名，查不到就让用户换个城市名。

**为什么必须锁定一个城市**（答辩会被问）：
- 公交接口的 `city1/city2` 只接受 adcode，传中文返回 20000 参数错误，传“全国”不可能——公交地铁本身就是城市内网络
- 地名解析可以不限城市，但“中山公园”全国几十个，不限会解析到外省（代码里有“离市中心超 60km 判错”兜底）

### 在线解析踩过的三个坑（改这块前务必看）
1. **直辖市 adcode**：`district?keywords=北京` 返回的是 `110100`（市辖区），不是 `110000`。拿 110100 去查 POI 会让
   `citylimit` 失效，候选点直接跨省乱窜（实测跑出厦门的集美学村、广州的嘉禾望岗）。所以直辖市一律归成 `110000`。
2. **站名不能去掉“地铁站”三个字**：`兆丰路(地铁站)` 规范成 `兆丰路地铁站` 能解析到花桥（19km），
   但纯 `兆丰路` 会匹配到同名的道路、偏到太仓方向（51km）。括号可以去，“地铁站”必须留。
3. **POI 搜索失败不能静默吞掉**：个人 Key 约 3 QPS，连打会返回 `10021`。如果吞掉错误，用户看到的是
   “这个城市没有地铁站”，实际是“查得太快”。现在限频错误会如实提示“查询太频繁，请等几秒再试”。

**要加一个“预置城市”**（想让下拉里直接有、且带固定示例数据）：改 `js/cities.js`，往 `CITIES` 里加一条
（key / name / adcode / center / stations / destExample / members）。多数情况用不着——直接用「其他城市」入口更省事。

**切换机制与硬约束**：`applyCity()` 靠给 `amap-api.js` 里 `AMAP_CITY` / `AMAP_CITY_ADCODE` / `AMAP_CITY_CENTER` 三个全局变量重新赋值来切城市，并替换 `MEETING_CANDIDATES`。所以这三个变量名**不许改、不许搬进闭包或对象**，否则切换会失效且不报错（这条已写进给雷馨怡的补充要求）。

注意：**三个变量必须一起改**。只改 `AMAP_CITY` 而忘了 `AMAP_CITY_CENTER`，所有地名会被“离中心超 60km”判错、集体降级成本地估算——不报错，但数据全假。

**自测任意城市**：`node test-any-city.js 长沙`（可带多个：`node test-any-city.js 长沙 桂林 昆山`），
看最后一行是不是 `✓ 降级 0`。

## 生成一次的耗时（演示时注意）

因为加了 350ms 请求间隔，一次三方案生成约需 **7~10 秒**（27 次请求左右）。按钮已有“正在计算方案…”的置灰状态，**不要连点**；答辩演示时可以先说一句“它在逐条查真实路线”，等结果出来再讲。

**候选集合点怎么选**：4 个点要分散在城市不同方向（如武汉取洪山广场/中山公园/循礼门/武昌火车站），全挤市中心会让部分成员绕远路，方案二会明显偏慢。
